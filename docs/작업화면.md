# 로컬 문서 작업 화면

작성일: 2026-10-26. `/`는 문서 작업 공간, `/lab`은 입력 관찰·편집기 실험실이다. 문서 중심의 실제 사용 흐름을 구현한 로컬 프로토타입이며 서버·인증 단계의 완료로 취급하지 않는다.

## 구현 기준

사이드바 페이지 트리, 얇은 상단 경로, 흰 문서 캔버스, 큰 제목·페이지 아이콘·커버, 커서 주변의 블록 핸들·슬래시 메뉴·텍스트 선택 도구를 사용한다. 자체 디자인 토큰·아이콘·CSS 그라디언트로 구성한다.

동작 참고: [Notion 작성·편집 기본](https://www.notion.com/help/writing-and-editing-basics), [페이지 만들기](https://www.notion.com/help/create-your-first-page), [페이지 꾸미기](https://www.notion.com/help/customize-and-style-your-content). 공개 문서에서 확인한 동작을 기준으로 삼았으며 로그인한 실제 노션 워크스페이스의 관찰 결과나 픽셀 일치 판정은 아니다.

## 저장과 데이터 보존

- IndexedDB `yotion-workspace`, `state` 저장소의 `workspace` 레코드에 `{ id, revision, data }`를 저장한다. 문서 원본은 페이지별 Tiptap JSON이다.
- 작업 공간 전체를 단일 원본으로 저장하며 서버 DB·파일 저장소는 아직 없다. 자동 저장은 600ms 디바운스, 저장 중 추가 수정은 직렬 후속 저장으로 처리한다.
- 단일 readwrite 트랜잭션에서 revision을 비교하고 갱신한다. 불일치·용량 초과·쓰기 오류는 성공으로 표시하지 않는다. 초기 데이터 읽기가 실패하면 기존 저장소를 초기화하지 않는다.
- 충돌 시 메모리의 사용자 변경을 유지하고 JSON 다운로드·저장본 교체를 제공한다. 저장본 교체 시 편집기도 다시 초기화해 이전 본문이 남지 않도록 한다.
- 한글 조합 중 블록 메뉴·슬래시 Enter를 적용하지 않으며 저장을 보류한다. 조합 종료 후 내용을 반영한다. 페이지를 바꾸기 전 현재 편집 JSON을 반영하며 미저장 상태에서 창 닫기 경고를 요청한다. 실제 IME 수동 검증은 별도다.
- 전체 스냅샷 단위의 낙관적 잠금이다. 탭마다 서로 다른 페이지를 편집해도 충돌할 수 있다. 서버 연결 전까지 협업이나 다중 탭 자동 병합을 제공하지 않는다.

## 페이지와 블록 규칙

- 페이지 이동은 순환 부모를 거부한다. 삭제는 하위 페이지를 함께 휴지통에 보관한다. 하위 페이지 복원 시 필요한 조상도 복원한다.
- 페이지 복제는 하위 계층과 내용을 복사하고 페이지·블록 ID를 새로 부여한다.
- 블록 이동은 최상위 블록 하나를 대상으로 하며 JSON과 ID를 보존한다. 드래그 외에 메뉴와 Alt+Shift+방향키를 제공한다. 다중 블록 드래그는 후속이다.
- 이동·복제·삭제는 타이핑과 별도의 undo 묶음으로 처리한다. 토글의 열림 상태를 바꿀 때 ID를 유지하는 NodeView를 적용한다.
- 본문 최상위 블록과 사이드바·즐겨찾기 페이지에서 우클릭 메뉴를 제공한다. 블록 ID·페이지 ID로 대상을 확정하며 현재 커서나 활성 페이지를 대신 사용하지 않는다. 블록 이동은 이미지 같은 비텍스트 노드도 명시적인 블록 시작 위치로 처리한다.
- 페이지 우클릭은 열기·즐겨찾기·이름 바꾸기·하위 페이지·복제·이동·JSON 내보내기·휴지통을 제공한다. 열기·이름 바꾸기·복제·하위 생성처럼 이동이 필요한 명령 외에는 활성 문서를 바꾸지 않는다. 이름 변경 시 제목을 선택한다.
- 메뉴는 실제 크기로 화면 가장자리 안에 배치하고 테마를 유지한다. 방향키·Home/End로 활성 항목을 탐색하며 Enter로 실행, Escape/Tab으로 닫고 원래 대상에 포커스를 돌린다. Shift+F10과 ContextMenu 키로도 연다. 외부 클릭·스크롤·창 크기 변경·창 비활성화·검색·브라우저 탐색 시 닫는다. 제목 등 일반 입력창의 기본 우클릭은 유지한다.
- 본문과 왼쪽 블록 버튼 사이의 여백도 편집기 hover 영역으로 포함한다. 본문 너비·위치는 유지하며 데스크톱은 56px, 좁은 화면은 28px의 버튼 접근 영역을 사용한다. 버튼 위에서는 대상 블록을 다시 선택하지 않는다. 편집 영역을 완전히 벗어나면 버튼을 숨긴다.
- 체크박스·토글·표·이미지 노드를 기존 문서 검증기에 추가했다. 이미지 주소와 속성·셀 병합·열 너비·불리언 값을 검사한다. 이미지 파일은 제한된 래스터 형식과 1 MiB 상한을 사용한다.
- 페이지 JSON은 새 페이지로, 작업 공간 JSON은 새 사본 묶음으로 가져온다. 작업 공간 가져오기는 계층을 재연결하고 새 ID를 부여한다. 기존 문서·테마는 덮어쓰지 않는다. 원본의 모든 내부 URL을 재작성하는 가져오기 모듈은 아직 없다.

## 자동 검증

macOS / Node.js 26.4.0 / Chromium 156.0.8078.4에서 검증한다.

2026-10-26 최종 결과: 타입 검사·프로덕션 빌드·단위 시험 30개·브라우저 시험 25개 통과. 기존 실험실 시험 6개, 작업 화면 시험 10개, 우클릭 메뉴 시험 5개, 블록 버튼 접근 시험 4개를 포함한다.

- 타입 검사, 프로덕션 빌드.
- 기존 문서·입력 단위 시험과 페이지 모델 시험: 시작 문서 스키마, 순환 이동 차단, 하위 구조 삭제·복원, 복제 ID 분리, 저장소 계층 검증.
- 실제 브라우저: 페이지 작성·자동 저장·검색·재열기, 이동·휴지통·복원, 슬래시 명령·체크박스·토글 ID·표, 블록 이동·복제·삭제·undo, 블록·페이지 드래그, 이미지·아이콘·커버 복원, 저장 실패·재시도, 두 탭 충돌·저장본 교체, 테마·본문 너비·모바일 배치, 작업 공간 JSON 재가져오기.
- 우클릭 회귀 시험: 커서와 다른 블록의 ID·이동·복제·삭제·undo, 비활성 페이지와 즐겨찾기 메뉴의 대상 구분, 페이지 이동·이름 변경·하위 생성·복원, JSON 내보내기 내용, 키보드 열기·탐색·실행·포커스 복원, 화면 끝 배치·재열기·스크롤·리사이즈·검색 시 닫기, 일반 입력창의 기본 메뉴 유지.
- 블록 버튼 접근 회귀 시험: 실제 마우스로 본문 → 여백 → 버튼을 여러 단계로 이동한 뒤 `+` 클릭·블록 추가, 1280px/390px 핸들 클릭·이동·undo, 핸들 드래그·ID 보존을 검증한다. 수정 전 4개 모두 여백 통과 시 버튼이 사라져 실패했고 수정 후 통과했다. locator 자동 클릭으로 여백을 건너뛰지 않는다.
- 데스크톱·다크·모바일·슬래시 메뉴 화면 캡처를 생성한다. 실제 IME나 노션 화면 비교 시험으로 대체하지 않는다.
