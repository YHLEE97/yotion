# 문서 JSON 실험 계약 v1

2026-10-26 / ARCH-01 초안. 편집 엔진 검증에 사용하는 로컬 교환 형식이다. 서버 저장·revision·권한은 아직 구현하지 않았으며 실제 IME 검증 후 확정한다.

메인 작업 공간은 IndexedDB에 자체 revision 조건부 저장을 사용한다. 서버의 revision·권한 계약과 구분하며 [작업 화면 기록](작업화면.md)에 정리한다. 아래 수동 저장·교체 전 복구 절차는 `/lab`의 동작이다. 메인 화면의 JSON 가져오기는 기존 내용을 유지하고 새 페이지·사본을 만든다.

## 원본과 교환 형식

```json
{
  "schemaVersion": 1,
  "content": {
    "type": "doc",
    "content": [
      {
        "type": "paragraph",
        "attrs": { "id": "example-block-1" },
        "content": [{ "type": "text", "text": "한글 문서" }]
      }
    ]
  }
}
```

현재 Tiptap StarterKit의 문서 JSON을 원본으로 한다. 가져오기·로컬 저장·저장본 열기는 공통 검증기를 거친다. HTML을 중간 표현으로 사용하지 않는다. 기본 속성은 스키마에 따라 채우며, 미지원 내용은 제거해 성공시키지 않고 거부한다.

- 최대 UTF-8 2 MiB, 문서 노드 20,000개(텍스트와 루트 포함), 루트 아래 최대 64단계.
- 문단·제목·목록·목록 항목·인용·코드·구분선·체크리스트·토글·표와 셀·이미지에는 문서 내 중복 없는 블록 ID가 필요하다. ID는 영문·숫자·밑줄·하이픈 1~128자다. text / hardBreak에는 별도 ID가 없다.
- 루트는 doc이며 스키마가 요구하는 블록 구조를 만족해야 한다. 빈 문서는 빈 paragraph 한 개로 표현한다.
- 미지원 버전·노드·서식·필드·속성, 손상 JSON, 잘못된 계층, 중복·누락 ID는 오류다. 버전 자동 추정·업그레이드는 하지 않는다.
- 링크는 http(s), ftp(s), mailto, tel, callto, sms, cid, xmpp, `/`로 시작하는 내부 경로와 `#` 앵커를 허용한다. 공백·제어 문자, 프로토콜 상대 주소와 스크립트 주소는 거부한다. 편집기와 가져오기가 같은 규칙을 사용한다.
- 파일명·MIME만으로 신뢰하지 않고 내용을 검증한다. 미리보기는 최대 2,000자의 일반 텍스트다.

## 적용과 복구

1. 파일을 선택하거나 로컬 저장본·복구본을 연다.
2. 전체 검증 후 파일명·블록 수·본문 텍스트를 미리보기로 보여준다. 현재 본문은 유지한다.
3. 사용자가 ‘현재 문서에 적용’을 누르면 그 시점의 본문을 검증하고 교체 전 복구본으로 저장한다.
4. 복구본 저장 성공 후에만 본문을 교체한다. 가져온 본문은 명시적으로 로컬 저장하기 전까지 기존 저장본을 덮어쓰지 않는다.
5. 취소·검증 실패·복구본 저장 실패는 본문을 바꾸지 않는다. 조합 중에는 적용할 수 없다.

복구본은 최신 한 개이며 다음 교체 때 갱신된다. 복구본을 적용할 때도 현재 본문을 복구본으로 바꾸므로 두 문서 사이에서 되돌릴 수 있다. 브라우저 저장 공간 삭제·브라우저 장애에 대비한 영구 백업은 아니다. 여러 탭의 로컬 저장 충돌 방지는 미구현이다.

저장 키는 `yotion:spike:document:v1`, 복구 키는 `yotion:spike:before-restore:v1`이다. 파일과 저장본 모두 동일한 버전 1 봉투를 사용한다. 입력 관찰 JSON은 별도 형식이며 문서로 가져올 수 없다.

## 서버 저장의 다음 설계

아직 구현하지 않은 서버 계약은 문서 조회 시 `schemaVersion`, `revision`, `content`를 반환하고 저장 시 `expectedRevision`을 받는 방향으로 잡는다. DB에서 현재 revision 비교·갱신을 하나의 트랜잭션으로 수행한다. 불일치는 409로 응답하고 현재 본문을 덮어쓰지 않는다. 워크스페이스 권한 검사는 조회·저장 모두 적용한다.

CORE-01 착수 전 PostgreSQL·마이그레이션과 인증 경계를 함께 확정한다. 로컬 교환 JSON을 서버의 권한·동시성 계약으로 취급하지 않는다.
