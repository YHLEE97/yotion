# 첫 개발 묶음: 입력 관찰과 편집 엔진

작성일: 2026-10-26. 구현 대상은 REA-02 / SPIKE-01이다. 실제 노션 동작이나 내보내기 파일을 관찰한 결과가 아니며, 아래 절차는 비교 검증용이다.

## 범위 기준선 (PLAN-01 초안)

| 사용자 흐름 | MVP 화면 | 첫 프로토타입 범위 |
|---|---|---|
| 문서 작성·저장 | 작업 화면 → 문서 편집 | 편집 엔진과 수동 로컬 저장 실험 |
| 문서 정리 | 페이지 트리·검색·휴지통 | 후속 |
| 외부 문서 가져오기 | 분석·미리보기·실행·보고서 | 입력 형식 관찰만 구현 |
| 백업·복원 | 설정·내보내기 | 편집 JSON 다운로드만 구현, 백업 아님 |
| 개인 계정·권한 | 가입·개인 워크스페이스 | 후속 |

실시간 공동 편집·DB·노션 API 연결은 초기 실험 범위에서 제외한다. 화면의 ‘개인 작업 공간’은 프로토타입 안내이며 실제 계정은 없다.

## 기술 선택과 되돌릴 조건

- Next.js / React / TypeScript 및 Tiptap StarterKit, UniqueID를 사용한다. [Next.js 연동 문서](https://tiptap.dev/docs/editor/getting-started/install/nextjs)에 따라 SSR 초기 편집 렌더링을 비활성화했다.
- 블록 ID는 [UniqueID](https://tiptap.dev/docs/editor/extensions/functionality/uniqueid) 확장으로 부여한다. 최상위 블록을 ProseMirror 트랜잭션으로 이동해 내용·ID를 유지한다. 다중 선택과 중첩 블록만의 이동은 미지원이다.
- 원본은 편집기 JSON이다. 로컬 실험용 봉투는 `{ schemaVersion: 1, content }`이며 [문서 저장 계약 초안](../문서저장계약.md)에 정리했다. 서버 revision 계약은 실험 완료 후 확정한다.
- 기본 StarterKit 노드만 사용하며 토글·체크박스·표·이미지는 후속이다. IME 안정성이나 중첩·이동 불변식이 깨지면 편집 모델과 확장 구성을 재검토한다.
- 설치 버전은 package-lock.json에 고정한다. 직접 사용하는 Next.js, React, Tiptap, UniqueID의 배포 패키지 라이선스를 확인하고 유료 Tiptap 확장은 사용하지 않는다.

## REA-01 / SPIKE-01 비교 절차

각 실행에 OS·브라우저 버전·IME·날짜·입력과 실제 결과·차이·증거 위치를 추가한다. 아래 ‘기대’는 Yotion의 시험 기준이며 노션 관찰 결과가 아니다.

| ID | 초기 상태와 입력 | 기대 | 노션 비교 / 수동 결과 |
|---|---|---|---|
| EDIT-001 | 빈 문단에 ‘안녕하세요’ 조합 → Enter | 마지막 글자 중복·유실 없이 한 번 분리 | 미관찰 / 미시험 |
| EDIT-002 | 문단 중간 Enter → Backspace | 분리·병합 후 원문 보존 | 미관찰 / 미시험 |
| EDIT-003 | 두 번째 글머리 항목 Tab → Shift+Tab | 중첩 후 원래 계층 복원 | 미관찰 / 미시험 |
| EDIT-004 | 두 번째 최상위 블록에서 ‘블록 위로’ → undo → redo | 순서 변경, ID·본문 유지 | 미관찰 / 미시험 |
| EDIT-005 | 조합 중 편집 도구·저장 버튼 관찰 | 도구 비활성화, 조합 계속 | 미관찰 / 미시험 |
| SAVE-EXP-01 | 한글 본문 → 로컬 저장 → 새로고침 → 불러오기 미리보기 → 적용 | 저장한 내용·ID 복원 | 노션 비교 대상 아님 / 자동 시험 통과 |

수동 샘플은 빈 문서, 한글+이모지 문단, 제목 1~3, 목록 3단계, 인용, 코드, 긴 문단을 각각 만든다. 30개 문서 회귀 자료는 후속 작성한다. 자동 문자열 입력은 실제 IME 조합 검증으로 간주하지 않는다.

## REA-02 입력 관찰 절차

1. Chrome / Edge의 버전·OS를 기록하고 ‘드롭 · 클립보드’ 화면을 연다.
2. 직접 만든 텍스트·HTML·링크·로컬 파일을 각각 드롭하거나 영역에 붙여넣는다.
3. 접근 권한이 있는 노션 테스트 문서의 단일 문단·다중 블록·이미지·페이지 링크도 같은 방식으로 관찰한다.
4. MIME 목록, items, 문자열 원문, 파일 메타데이터를 확인하고 JSON을 내려받는다. 잘림 표시가 있는 샘플은 전체 보존 근거로 사용하지 않는다.
5. 같은 입력의 드롭과 붙여넣기, Chrome과 Edge 결과를 비교한다. 빈 전달 데이터나 브라우저 제한도 결과로 기록한다.

원문 HTML은 React 텍스트로 표시하며 실행·미리보기하지 않는다. 파일 본문과 디렉터리 탐색은 하지 않는다. 이 관찰 도구는 가져오기 변환기나 HTML 정제 구현을 대체하지 않는다.

## 검증과 남은 조건

자동 검증: 블록 ID 부여·JSON 재열기, 이동·undo/redo, 목록 중첩, 입력 잘림·HTML 원문 기록, 브라우저 저장·재열기와 드롭 처리.

2026-10-26 실행 결과 (macOS / Node.js 26.4.0):

| 검사 | 결과 |
|---|---|
| TypeScript 타입 검사 | 통과 |
| Vitest | 22개 통과: 기존 편집·입력 관찰, JSON 왕복과 잘못된 버전·구조·ID·주소·크기·중첩 제한 |
| Playwright / Chromium 156.0.8078.4 | 6개 통과: 기존 3개 흐름, JSON 다운로드·재가져오기·교체 전 복구, 손상 파일·저장본·취소 시 본문 유지, 복구본 저장 실패 시 교체 중단 |
| Next.js 프로덕션 빌드 | 통과 |

목록 키보드 시험은 클릭 후 편집기 선택 위치가 갱신된 것을 확인하고 입력한다. 브라우저의 DOM 선택 표시와 ProseMirror 선택 갱신은 같은 시점이 아닐 수 있다. 선택 위치는 문서 구조 검사기에 표시한다. IME 관련 자동 시험은 합성 이벤트의 UI 상태만 검증한다.

직접 사용 패키지의 배포 메타데이터 확인: Next.js 16.4.3, React 19.3.1, Tiptap React / StarterKit / UniqueID 3.32.0 모두 MIT. 전체 전이 의존성은 잠금 파일에 기록한다.

REA-02의 Chrome·Edge 실제 외부 입력 샘플, SPIKE-01의 실제 한글 IME, 노션 비교 관찰 및 REA-03 내보내기 ZIP 분석은 미완료다. 이 조건이 남아 있으므로 후속 ARCH-01 / CORE-01의 완료를 선언하지 않는다.
